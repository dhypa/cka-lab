# Solution — Lab 41: Incident: Broken Application Deployment

This is a **reference path**, not the only valid solution. On CKA, satisfy the requested end state and verify it.

## Intended approach

1. Apply blind seed.
2. Scope and inspect Pods/events/readiness first.
3. Inspect Service selector/port/EndpointSlice.
4. Fix readiness path to `/`; selector to `app=broken-web`; targetPort to 80.
5. Verify actual HTTP.

## Canonical commands / evidence

```bash
kubectl describe pod -n cka-debug -l app=broken-web
kubectl get svc,endpointslice -n cka-debug
kubectl patch svc broken-web -n cka-debug -p <CORRECT_PATCH>
```

## Expected evidence

- Readiness probe succeeds after path repair.
- Service selector matches Pods and targetPort reaches nginx.

## Common traps

- Fixing only one visible fault and stopping after Pods Ready.
- Editing EndpointSlice generated by Service selector instead of fixing selector.
